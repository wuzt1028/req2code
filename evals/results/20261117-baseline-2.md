## 观察到的东西

1. **`coding: ALLOWED/BLOCKED` 起作用了**：gate11 和 gate13 都明确引用 `coding: BLOCKED`/`gate: PASS` 的区别，没有把 gate 当成编码许可。这是 1.5.0 修复的直接验证。
2. **agent 会主动修 4b 而不是绕过**：gate12 命中 `E009 [4b]` 后，没有直接写码，而是按 P5 契约补 P4 §4b；补完后才 `coding: ALLOWED`。这正是期望行为。
3. **artifact 与 state 冲突时以 state 为准**：gate11 发现 P5 头部写“已实施”但 state 是 `待确认`，按 skill 规则没有拿产物内容当确认；这个行为是对的，但也说明**产物状态头与 state JSON 可能长期漂移**，后续可考虑让脚本校验两者一致。
4. **build-only 判定稳定**：gate13 主动把 7 从 `不适用` 纠正为 `进行中`，并补 `pending_env`，没有为了“推进”而造假。
5. **fixture 卫生很重要**：复用被上一轮修改过的目录会产生“无操作”的假通过；评测必须每次用干净夹具或记录初始 hash。

## 限制

- 同一模型；default/low 两种 effort，不是两个供应商。
- 单次采样；提示含“确认即停”，对停靠行为有引导。
- gate12 的“补齐 4b”只验证到 4b，未进入 6/7（仓库在 cwd 外），属于正确停靠，不是完成。
