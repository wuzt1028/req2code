# 外部 skill 与 MCP 集成

优先调用外部 skill 增强质量；缺失或调用失败时，使用本文内置 rubric 降级，不阻塞流程。

## 一、可用性判定

调用外部 skill 前，按以下标准判定是否可用：

1. **在列表中**：当前会话的可用 skill 列表中存在该名称（Claude Code / OpenCode / Codex 均在系统提示中暴露 skill 列表）。
2. **可被模型调用**：frontmatter 带 `disable-model-invocation: true` 的 skill（如 `grill-me`、`implement`、`handoff`）只能由用户手动触发，模型不得自动调用，一律按「不可用」走降级。
3. **调用未报错**：调用失败（skill 不存在、执行错误）时立即降级，不重试、不硬失败。

规则：

- 降级执行时，在产物文件中标注 `Fallback: {工具} unavailable -> {替代方式}`，保持透明。
- 同一次会话内多个关键增强 skill 缺失时，向用户**一次性**提示缺失清单与降级影响（说明安装后可获得更好效果），不阻塞流程、不反复提醒。
- 用户手动调用了某个增强 skill（如 `/grill-me`、`/handoff`）时，按其结果继续，无需降级。

## 三、内置降级 rubric

### PRD rubric（prd-writing 缺失时）

- 有证据：问题背景含数据/用户引述/现象；无证据必须显式标注「无证据，观点驱动」
- 目标量化：每个目标带数字；每个指标配反指标
- 用户具体：「谁 + 什么情境 + 为什么需要」，禁止"产品经理"这类宽泛描述
- 优先级：P0 限 3-5 条；每条一句话；超出的降级或拆分
- 边界：必须有「明确不做」；缺边界视为不合格
- 禁词：improve/enhance 类无数字的模糊目标
- 篇幅：800-1200 字为宜；超过说明思考未完成

### 需求澄清追问清单（grilling 缺失时）

逐条挑战，每题给 2-4 个选项让用户决策：目标可量化吗（指标/反指标）→ 场景真实吗（谁/频率/现状）→ 边界清晰吗（不做什么）→ 优先级对吗（P0 能否砍到 3-5 条）→ 约束漏了吗（技术/合规/时间/依赖方）→ 证据充分吗（哪些观点驱动、需要向谁确认）。

### UI finish gate rubric（anti-ui-slop 缺失时）

- 反模板感：页面是否有明确的风格来源，能否一眼看出属于参考产品的设计语言
- 状态完整：加载/空态/错误态/禁用态（含权限不足态）是否全部覆盖
- 响应式：断点行为是否明确且自洽
- 可访问性：对比度、键盘可达、焦点可见、语义化标签
- 一致性：与参考源的偏离项是否逐条说明原因
- 结论：任一项不达标即整改后再交付

### 视觉方向三问（无参考源且 frontend-design 缺失时）

问用户：受众是谁（谁看、什么场景）→ 首要任务是什么（界面服务于什么动作）→ 想留下什么记忆点（唯一一处差异化）。方向经用户确认后再实现，禁止自由发挥。

### Code review 清单（code-review 缺失时）

- 契约一致：接口路径/字段/错误码与 `P5-开发设计.md` 一致
- 复用检查：是否存在可复用组件被重复实现
- 错误处理：异常分支、边界值、空值、并发/幂等
- 兼容性：向后兼容；破坏性变更已标注并确认
- 风格一致：符合仓库既有命名/分层/写法
- 安全：鉴权、越权、注入、敏感信息（触发安全敏感改动时转 security-audit）
