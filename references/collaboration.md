# 多会话协作

主会话 + 辅助会话的并行协作模式。主会话是需求与决策的唯一事实来源，辅助会话只负责执行并把结论同步回来。

## 一、角色分工

| 角色 | 职责 | 边界 |
|---|---|---|
| **主会话** | 需求澄清、关键决策、范围控制、最终验收；维护产物文件 | 不并行写码，避免与辅助会话冲突 |
| **后端会话** | 接口设计落地、数据查询与实现、后端联调 | 不改需求/设计；发现问题回报主会话 |
| **前端会话** | 页面实现、交互调整、浏览器联调 | 不改接口契约；发现问题回报主会话 |
| **测试会话** | 测试场景、接口验证、回归检查 | 不改代码；输出 bug 清单回报主会话 |

## 二、可用性检查（先检查再决定走哪条路）

spawn 前检查：

1. 当前不在子代理上下文；
2. Agent/Task 工具可用；
3. 运行环境支持自定义 agent（Claude Code: `Agent(...)`；OpenCode: `task` 工具；Codex: 自定义 agent registry）。

任一不满足 → 走「无 subagent 降级」。

## 三、subagent 模式（可用时）

按结构化 prompt spawn，必须携带产物目录与回报格式：

```
Agent(subagent_type: "{backend|frontend|tester}-agent", prompt: "
需求目录：{产物目录}
任务类型：{后端实现|前端实现|测试执行}
输入文件：
- {产物目录}/P1-PRD.md
- {产物目录}/P3-交互原型.html
- {产物目录}/P5-开发设计.md（相关章节）
约束：严格遵循仓库约定与设计契约；不引入新依赖；不自行改需求/设计
回报格式：
【结论】...
【影响文件】...
【待决策项】...
")
```

说明：

- agent 类型不存在时，用 `general` 类型并携带同样的结构化 prompt。
- 同一批次的任务拆分要按「前端 / 后端 / 测试」职责切分，不交叉写码。
- 主会话收到回报后：更新产物文件 → 决策待决项 → 再派发下一批。

## 四、无 subagent 降级

无法 spawn 时，引导用户开辅助会话（agent 工具通常支持主会话 + 辅助会话并行，把会话 ID 传给主窗口）：

1. 主会话产出「派发单」：任务描述 + 输入文件绝对路径 + 约束 + 回报格式（即上节 prompt 内容）。
2. 用户将派发单粘贴到辅助会话执行。
3. 辅助会话完成后，把以下格式的回报粘贴回主会话：

```
【结论】做了什么、结果如何
【影响文件】改动的文件清单（绝对路径）
【待决策项】需要主会话决策的问题
```

4. 主会话据此更新产物文件并继续。

## 五、并行时机

| 时机 | 可并行的会话 | 前提 |
|---|---|---|
| Phase 3-4 期间 | 测试会话准备测试点/用例 | PRD v2 已确认 |
| Phase 5 确认后 | 后端会话 + 前端会话并行编码 | 开发设计已确认 |
| Phase 6/7 期间 | 测试会话按 Case 预演 | 测试 Case 就绪 |
| Phase 8 | 主会话主导联调验收，测试会话执行回归 | 前后端改动完成 |

## 六、冲突与同步规则

1. 需求冲突：一切以主会话确认的 PRD v2 为准；辅助会话发现与 PRD 不符 → 停止执行并回报。
2. 设计不可行：辅助会话回报「待决策项」，主会话回 Phase 5 更新开发设计，再重新派发。
3. 接口契约争议：以 `P5-开发设计.md` 为准；需要调整时由主会话更新设计后统一通知。
4. 所有辅助会话结论必须落回产物文件（`P5` 实施状态 / `P8` 验收记录）并同步更新 `_状态.md`，否则视为未完成。
5. 会话交接：需要跨会话续跑时，提示用户手动执行 `/handoff`（该 skill 仅用户手动触发，模型不自动调用），或按上述回报格式把「当前阶段 + 产物路径 + 未决项」压缩成一段交接说明。
